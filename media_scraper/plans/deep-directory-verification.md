# 深目录验证方案

状态：2026-10-07 已用现有 `main.py` 跑过，未改产品代码。下面是实测结果。

## 要确认的事

扫描使用 `os.walk`，按层向下走，文件夹层数本身不会撑爆 Python 递归栈。Windows 上真正会失败的是路径长度：单个名字大约 255，整条路径大约 260。

输出文件名已有截断（单段约 200 字、整条路径约 240，见 `rename/renamer.py` 的 `SAFE_COMPONENT_LEN` / `SAFE_FULLPATH_LEN`）。源文件所在的深路径如果已经超长，扫描、建目录、移动仍可能失败。

## 怎么验

不使用真实片库。在临时目录造假视频（几十字节、视频扩展名），只走本地归档，不联网刮削。

1. 短文件夹名，分别嵌套 8 层、20 层、40 层。确认都能扫到，并移动到目标单片文件夹。
2. 再造一条总长度超过 260 的路径。分别记录扫描、建目录、移动哪一步失败，以及错误是不是路径过长。
3. 结果记三件事：最深成功层数、第一条失败路径的字符数、失败发生在扫描还是移动。

做成自动测试，以后改扫描或移动时重复跑。

## 2026-10-07 实测

入口：`media_scraper` 下的 `python main.py scan`，然后 `python main.py scrape --apply`。临时目录 `D:\msv_depth_test`，跑完已删除。文件名用 `テスト.mp4`，程序识别为本地标题，没有联网。现有配置忽略小于 10MB 的文件，所以假视频按这个大小写。本机注册表 `LongPathsEnabled` 为 0。

| 用例 | 结果 |
| --- | --- |
| 8 层，源路径 48 字 | 扫到 1 个，移入 `テスト\テスト.mp4`，写出 NFO |
| 20 层，源路径 73 字 | 同上 |
| 40 层，源路径 113 字 | 同上 |
| 110 层，源路径 254 字 | 扫描成功。移动时创建目标文件夹失败：`WinError 206`（文件名或扩展名太长）。视频仍在原处，没有 NFO。进程退出码 1 |
| 源路径 256 字 | 文件夹建不出来，同样是 `WinError 206`。程序还没开始 |

目标文件夹比源目录多一层标题名。源目录大约 246 字时文件还能创建；再加 `テスト` 后目录大约 250 字，`os.makedirs` 失败。再长到目录大约 248 字时，源文件夹本身也建不出来。这和 Windows 在未开启长路径时、目录大约 248 字的上限一致。

失败发生在移动阶段的建目录，不是扫描。扫描能读到 254 字的源文件。这次失败没有收成单文件跳过，整次执行被异常打断。

## 先不做

- 不改 `scanner.py`、`pipeline_apply.py` 的路径处理。
- 不给现有文件加 `\\?\` 长路径前缀，除非上面的超长用例证明当前环境会失败。
